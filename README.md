# Cumulus

London community events: discover what's on (feed + live map), book tickets
(free or paid via Stripe), carry them in a wallet with QR codes, and host your
own events with payouts. Installable as a PWA, with iOS/Android shells in
`native/`.

**Live:** https://cumulusapp.co, deployed by Vercel from `main`.

---

## Quick start

There's no build step. The app is static HTML/CSS/JS served as-is.

```bash
npm install
```

```bash
npm run serve
```

Then open http://localhost:3457. The app talks to the live Supabase project in
`src/js/config.js`.

- **Map:** needs network access to `api.mapbox.com`.
- **Payments:** need `js.stripe.com`.

### Tests

```bash
npx playwright install chromium
```

```bash
npm test
```

```bash
npm run check
```

- `npx playwright install chromium` is needed once, to get a browser for the tests.
- `npm test` runs the Playwright smoke tests: 78 checks across mobile and desktop.
- `npm run check` is fast: it syntax-checks every script and confirms that
  `index.html` and the service worker only reference files that exist.

CI runs both on every push and pull request (`.github/workflows/tests.yml`).

## Repo map

| Path | What it is |
|---|---|
| `index.html` | App shell: meta tags, third-party scripts, and the ordered `<script>` list |
| `src/js/config.js` | Public runtime config (Supabase URL + anon key, Mapbox token, Stripe publishable key) and the `sb` client |
| `src/js/services.js` | Data access: every Supabase query/RPC the UI uses |
| `src/js/app/01–14-*.js` | The UI, as 14 classic scripts sharing one global scope (see ARCHITECTURE.md) |
| `src/css/styles.css` | Base layer (older). Variables, resets, legacy components |
| `src/css/v2.css` | Current design layer. Wins over `styles.css`; new styles go here |
| `sw.js` | Service worker: precache + offline. **Bump `CACHE` on every release** |
| `assets/` | Icons, flyers for test events (`assets/flyers`, generated by `scripts/gen_flyers.py`) |
| `supabase/migrations/` | Database schema, RLS policies, RPCs, triggers, cron (applied in filename order) |
| `supabase/functions/` | Edge Functions (Deno): payments, refunds, payouts, emails, account deletion |
| `native/` | Capacitor iOS + Android shells that load the live site (see `native/README.md`) |
| `tests/smoke.spec.js` | Playwright smoke suite |
| `docs/history.md` | The original long-form dev log: decisions, incidents and why things are the way they are |
| `DESIGN.md` / `PRODUCT.md` / `GO-LIVE.md` | Design language, product notes, launch checklist |

## How a change ships

1. Edit files and run `npm run check && npm test`.
2. If you changed anything the browser caches, bump `CACHE` in `sw.js`
   (`cumulus-vNN`). Otherwise returning users keep the old files.
3. Push to `main`. Vercel deploys the static files in about a minute.
   `.vercelignore` keeps docs, tests and server code out of the deploy.
4. **Database changes:** add a new file to `supabase/migrations/` and apply it.
   Never edit an applied migration.
5. **Edge Function changes:** deploy with
   `supabase functions deploy <name>`. Functions verified by Stripe or cron
   signatures use `--no-verify-jwt`; see the header comment in each function.

## Accounts and access

- **Sign-in:** a 6-digit email code (Supabase OTP). No passwords.
- **Roles:** member, approved host (`verified-host` badge, granted when an
  admin approves a host application), and admin (row in `public.admins` plus
  an admin OTP step). Access is enforced by RLS and `SECURITY DEFINER` RPCs
  that check `is_admin()`. The client-side checks only hide UI.
- **Test data:** Admin tab → **Load stress test** / **Wipe stress test**
  creates or removes 100 test hosts and 216 events at real London venues.
  Everything is tagged `#cumulus-stress-test`, and the hosts use
  `@cumulus-test.invalid` emails.

## Secrets

Client keys in `config.js` are publishable by design. Server secrets live
only in Supabase Edge Function secrets. Names are in `.env.example` and in
ARCHITECTURE.md → Server.
